# Design: record & artifact integrity (Tier 1, branch 1 of 4)

**Date:** 2026-08-06
**Status:** Approved
**Source:** external v0.5.3 review, validated finding-by-finding against the current tree. Evidence: `.superpowers/sdd/validation/v053-validation.md`.
**Depends on:** PR #13 (`feat/first-run-ux`) merging first — finding 1 completes the record contract that PR made explicit.

## Why this is four branches, not one

Validation confirmed 38 of 40 review claims. Thirteen are wrong-answer or
data-corruption class. Shipping all thirteen together would repeat the mistake
PR #13 nearly made: at 19 commits it was already at the edge of what one
reviewer can hold in context, and its most serious defects were found only
because each task had a scoped gate.

The split groups findings a single reviewer can judge against **one** set of
constraints:

| Branch | Findings | Governing constraint |
| --- | --- | --- |
| **1 — record & artifact integrity** (this spec) | events after `RunFinished`; `${fake:*}` collision; `.map.json` phantom captures; inverted sidecar span | `proef-core` sans-IO; ADR-0008 event contract; ADR-0010 artifacts-as-contract |
| 2 — CLI output & exit integrity | non-UTF-8 env vars; `--output json` exit code; Tee duplication; `fmt` CRLF; `report -o` links; `diff` misattribution | exit-code contract (ADR-0009) |
| 3 — phase lifecycle | `--dry-run` skips phase validation; Ctrl-C skips teardown | ADR-0014, and needs an **amendment** — see below |
| 4 — LSP rooting | `initialize` params ignored; unbounded walk | ADR-0017 |

Branch 1 goes first because finding 1 completes PR #13's work rather than
opening a new front. Branch 3 is last of the code branches because it is the
only one whose fix is a **policy decision**, not a defect repair.

## Scope of this branch — four findings

### F1 — events are appended after `RunFinished`

`docs/EVENTS.md:9-10` states "the last is `run_finished`". Reproduced against
the real unmodified runner: a watchdog-abandoned scenario's detached thread
notices the cancellation token only at its next batch boundary, and keeps
emitting after the sweep has already written that scenario's
`ScenarioFinished` — and, worse than the source review claimed, **after the
run's `RunFinished`**.

Pre-existing: the contract wording predates this work (`91bdd59`). PR #13
guaranteed exactly one head/tail pair without guaranteeing the tail is last, so
this closes the same contract rather than opening a new one.

**Bug fix, no new ADR.** The contract already exists; the code violates it.
ADR-0007 (cancellation) is the governing decision and is unchanged — abandonment
stays cooperative; what changes is that a closed scenario's late events must not
reach the sink.

Fix direction: drop or divert events for a scenario the run has already
finalized. Prefer a sink-level or runner-level gate over asking every emitter to
check — one mechanism, not a discipline. The sans-IO constraint holds: this is
pure bookkeeping over data already in hand.

### F2 — `${fake:*}` values collide across steps

Reproduced: two steps each containing a fresh `${fake:email}` emitted the
**identical** address. `resolve()` builds a `Resolution::default()` per call
(`crates/proef-core/src/resolve.rs:169`), the occurrence counter lives on it
(`:317`), and `resolve()` is called once per step — so the counter restarts at
every step and `fake::generate(run_id, occurrence, kind)` returns the same value.
`docs/AUTHORING.md` reads as though each reference is independent.

**This changes generated bytes, and that is expected.** Artifacts are
snapshot-locked (ADR-0010), so snapshots covering `${fake:*}` **will** move.
They must move deliberately — `cargo insta review`, never blind acceptance —
and the diff must show only fake values changing.

The reproducibility guarantee survives **if and only if** the new counter scope
remains a pure function of inputs the run already fixes: same `run_id` and same
suite must still produce the same artifacts. Widening the counter to the
scenario satisfies that; anything keyed on wall-clock, iteration order, or
thread identity does not, and would break both ADR-0010 and core purity.

Whether the correct scope is per-scenario or per-run is settled during
implementation by which one keeps `${fake:*}` distinct *and* deterministic; the
plan must state the choice and show the determinism test.

### F3 — `.map.json` gains phantom capture rows

Reproduced: the `capture_names` scan (`crates/proef-core/src/emit.rs:249-296`)
is fence-unaware, so a fenced `[Captures]` line re-arms it, and it does not
recognise custom methods — a `PROPFIND` entry fails to terminate the scan.
Phantom rows land in `.map.json`, which is a **normative artifact**.

`crates/proef-core/src/lower.rs` already contains a correct method recogniser.
Share it rather than writing a second one — one canonical mechanism.

### F4 — whitespace-only `expect:` produces an inverted span

Reproduced: a whitespace-only `expect:` fragment yields `MergedAsserts { lines: 0 }`
and a sidecar span of `[9,8]` — start greater than end — from the
`start + lines - 1` underflow at `emit.rs:211`.

Two defensible fixes: reject the empty fragment at pack-validation time (a new
`empty_expect` diagnostic, matching how the project already rejects zero-entry
payloads), or make the span computation saturate. **Prefer rejecting at
validation.** An empty `expect:` is authorial dead weight with no meaning, and
the project's stated posture is to fail loudly rather than emit something
degenerate. A saturating span would produce a valid-looking artifact for input
that means nothing.

If validation rejection proves to break existing corpora, fall back to
saturation and record why.

## What is NOT in this branch

- The six CLI output/exit findings (branch 2).
- `--dry-run` phase validation and Ctrl-C teardown (branch 3). The latter needs
  an **ADR-0014 amendment**: the ADR gates teardown on setup-success and is
  silent on cancellation, so "should cleanup run when the operator interrupts"
  is an unanswered policy question, not a bug with an obvious fix. Answering it
  in a code PR would set policy by implementation.
- LSP rooting (branch 4).
- All Tier 2/3 findings — 24 maintainability and docs-drift items, separately
  recorded.

## Breaking-change treatment

F2 changes emitted artifact bytes for any suite using `${fake:*}`. Anyone
snapshot-testing proef's output sees a diff. PR #13 already forces **0.6.0**
(the empty-scenario diagnostic), so this rides that same minor release; the
changelog must state the artifact change under `### Changed`, not bury it under
`### Fixed`.

F1, F3 and F4 change output only where it was previously wrong.

## Testing

| Finding | Test |
| --- | --- |
| F1 | a watchdog-abandoned scenario's record has `run_finished` as its **last** line — assert on line position, not mere presence |
| F2 | two steps in one scenario with the same `${fake:kind}` produce **different** values; and a second run with the same `run_id` reproduces both exactly |
| F3 | a pack with a fenced `[Captures]` line and a `PROPFIND` entry produces a `.map.json` with no phantom rows |
| F4 | a whitespace-only `expect:` is rejected (or, if saturation was chosen, produces a non-inverted span) |

Every test must fail without its fix, demonstrated. This branch's source review
found four vacuous tests in the preceding work; assertions that target a proxy
rather than the property are the specific hazard — F1's test in particular must
assert *position*, since asserting presence would pass today.

## Constraints

- `proef-core` stays sans-IO: no IO, clocks, env reads, or randomness. All four
  fixes are pure computation over data already in hand.
- No new dependencies; hurl pins stay `=8.0.1`.
- Event schema is additive-only (ADR-0008) — F1 changes *ordering*, not shape.
- Artifacts-as-contract (ADR-0010): F2 and F3 move snapshots; every move is
  reviewed and justified, never blind-accepted.
- One canonical mechanism: F3 shares `lower.rs`'s method recogniser; F1 gates
  centrally rather than per-emitter.
- No task ids or plan numbers in code comments; no AI-attribution trailers.
